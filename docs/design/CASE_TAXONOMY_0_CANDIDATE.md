# CASE-TAXONOMY-0 candidate — no Authority change

Status: proposal only, 2026-10-14. No taxonomy enum, writer, migration or
classification backfill is implemented by CASE-CL0 / BRAND-UI-1.

The read-only census of the actual main Canonical Root found 12 approved Cases,
0 with an independent formally confirmed video-structure type, and 0 shared
display receipts. Existing `observed_source_profile`, operator hints, human
classification profile and Pattern/Compatibility describe production expression
or structure compatibility; none is a separate video-type dictionary. No title
keywords were used to infer a type. The machine census is retained in
`.local/evidence/brand-ui1-cl0-20261014/legacy-compatibility-taxonomy.json`.

A minimal future contract could have one versioned taxonomy registry with stable
IDs, display names, definitions, examples and explicit version/retirement rules.
A separate additive human label companion would bind exact Case ID and approved
SHA, registry version/type ID, stable authorized principal, timestamp, source
evidence and prior label SHA. This would remain independent of original Case
Approval, Fingerprint, Pattern, production profile and Compatibility. No label
would grant media rights or production eligibility. Withdrawn/unknown registry
versions must degrade accurately, without rewriting old approval history.

Founder/Classification Authority must first approve the vocabulary, whether one
or several types may be selected, reviewer responsibility, and correction rules.
The screenshot examples are not proposed as an approved enum. Legacy coverage
starts at 0/12; new and old Cases require deliberate human classification, without
automatic title-based migration. Until that separate decision, lists show
“视频类型暂未标注” and omit the unavailable type filter.
